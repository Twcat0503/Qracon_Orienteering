## 3. 與現有規格的差異

### 3.1 範圍被砍（影響最大）

便條 `2020:333` 原文：

> 精簡版刪掉了原本規劃的交流板和議程重點彙整（這兩項較複雜），保留優先級高的功能

對照我方文件：

| 項目 | `00-requirements.md` | 設計板 |
| --- | --- | --- |
| 交流版 | §7 完整章節 + ACC-6 | ❌ 未出現 |
| 議程重點彙整 | §5.6 + 計分 20/+30 + ACC-8 | ❌ 便條說砍了，但 `2:1330` 仍列「議程重點彙整 20 (+30) QXP」 |
| SSS 升級條件 | 「彙整通過 **或** 場外任務」 | 若彙整砍掉 → 只剩場外任務 |

**好消息**：`02-development-plan.md` 的 R3（審核塞車 37.5 人時）與 Q-6 直接消失，省下一個人工排班與一整套審核後台。

### 3.2 新增的頁面（我方文件沒有）

| 新頁面 | 影響 |
| --- | --- |
| **任務總版** | 依「當前時段」列出可做任務與已完成任務。需要一個新 API：依 server time 找出當前時段開放的任務。這是僅次於地圖的互動核心 |
| 內容標籤頁 + 知識類別總表 | 等於回答了 `Q-9`：**需要獨立頁**（我先前的建議是錯的） |
| 先備知識頁 | 難度 ★★ 以上的議程要另一頁，不是折疊區塊 |
| 冒險任務頁 | 每場議程的任務與分數要能被單獨瀏覽 |
| 冒險證書 | 可生成圖片（前端 canvas / satori，不需後端） |
| 量子探索推薦 | 會後頁面；若做個人興趣，需要額外問卷 |

### 3.4 流程細節變動

- **答題時窗**：設計板寫「講座**最後 5 分鐘**開放，半小時後關閉」；HackMD 寫「QA 時間開放」。以設計板為準，實作上更好排（不必等 QA）。
- **登入**：設計板定為「票號（綁定 KKTIX）＋ 密碼」，等於回答了 `Q-5` 的方向（不用 Email、不用 Google），但驗證機制未寫。
- **顏色**：設計板明確使用六類顏色 → 回答了 `Q-2`：**要彩色**，不是灰階。

### 3.5 地圖結構（與我方建議一致）

設計板 `2:1243`：

> 橢圓節點共有兩種：議程（如講座 A、場外互動等）、內容標籤（如量子退火、組合最佳化、拓樸 Qubit 等）。黑色實線為議程的核心概念，連接著議程和內容標籤；黑色虛線則連接著相關的兩個內容標籤。

這正是 `00-requirements.md` §5.4 建議的「議程 ↔ 標籤二部圖」：資料驅動、節點可展開、不用手畫連線。可以直接照做，`slot_tags` 就是圖的邊。

## 7. 讀取方式與限制（給後續的人）

- **Figma MCP（Framelink `get_figma_data`）讀得到結構，讀不到 FigJam 表格文字**。depth 開到 4 也一樣：`TABLE_CELL` 的 `characters` 不會輸出。文字要用 REST API：

```bash
TOK=$(cat ~/.config/mcp/figma-token.txt)
curl -s -H "X-Figma-Token: $TOK" \
  "https://api.figma.com/v1/files/T870RHckITgCICW4VrvAKW?depth=6" > board.json
```

- 表格文字在 `TABLE_CELL.characters`；用 `absoluteBoundingBox` 的 y 分行、x 排序，就能還原表格。
- 檔案約 100 KB（depth 6），一次抓完比逐節點呼叫快。
