## 1. 現實檢查：這個專案的真正瓶頸不是寫程式

三個不可壓縮的外部依賴：

| 依賴 | 前置 | 硬期限 | 錯過的後果 |
| --- | --- | --- | --- |
| **NFC 徽章製作** | 設計稿 → 打樣 → 下單 → 生產 → 海運／報關 → 清點 | **11/20 下單**（500 個 5cm 吊飾 + 配件） | 活動日沒有徽章，整個「帶走成果」的收尾消失 |
| **人工審核量能** | 排班 + 後台 | 活動日前完成訓練 | SSS 無法現場結算，配件發不出去 |
| **議程／題庫凍結** | 議程組 + 講者 | 議程 12/01、題庫 12/05 | 地圖與答題上線即過期 |

### 1.1 審核量能算給你看（決定 Q-6）

假設 500 人中 30% 投稿重點彙整 = 150 篇：

| 模式 | 每篇耗時 | 總人力 | 一天內可行？ |
| --- | --- | --- | --- |
| 全人工 | 15 分 | 37.5 人時 | ❌（現場僅約 16 人時可用） |
| 人工初篩 + AI 預審排序 | 5 分 | 12.5 人時 | ⚠ 勉強 |
| **AI 判分 + 人工只處理邊界與抽查** | 1 分 | 2.5 人時 | ✅ |

→ 建議 Q-6 採 **(b)**：AI 通過即給 50 分（20 即時 + 30 於 15 分鐘內由工人按「核准」），人工僅處理 AI 分數 45–65 的邊界案例與隨機抽查 10%。若現場人力仍不足，降級為「AI 通過即全額、事後抽查撤銷」。

## 4. 技術架構（摘要，細節見 `03-architecture-and-data-model.md`）

```
[手機瀏覽器]
   │  HTTPS
   ▼
[Cloudflare] ── Workers（Astro SSR + API）
   │                ├── D1（SQLite）：使用者、帳本、提交、議程
   │                ├── R2：上傳檔案（若允許附件）
   │                └── Cron：答題時窗關閉、每日備份
   ├── AI 審（Workers AI 或 Gemini API，JSON schema 輸出）
   └── 靜態資源（CSS/JS/字型）走 CDN
```

選型理由：

| 選擇 | 理由 | 替代方案 |
| --- | --- | --- |
| Astro 7 SSR | 與主站同技術棧，設計 token 可共用；多數頁面可靜態化，只有任務頁需 SSR | SvelteKit（團隊沒經驗，不換） |
| Cloudflare Workers + D1 | 主站已在 CF；500 人規模足夠；部署與回滾快 | 小型 VPS + SQLite（運維負擔高） |
| 原生 CSS + CSS 變數 | 與主站一致；不引入 Tailwind | — |
| 無前端框架、Vanilla TS islands | 減少 bundle 與除錯面；地圖用 SVG + DOM | React（多 40KB 與一個心智模型） |

**與主站的關係**：不共用程式碼，只共用 (1) 設計 token (2) `agenda.json`。主站不動。

## 7. 崩潰計畫（時間不夠時）

若 **11/27（G3）** 未能完成「登入→答題→得分→升級→掃碼」：

1. 砍掉網站任務（答題、心得、交流版、彙整）→ 只留登入 + 掃碼計分 + 地圖 + 結算。
2. 等級改用「現場任務 + 提問」判定（S=3 次任務、SS=5 次、SSS=7 次）。
3. 心得與彙整改為「紙本／Google Form 收件，會後人工整理」。
4. 徽章落地頁改為靜態成果頁（每人一頁，會後寄連結）。

這個降級版本仍能保住「冒險地圖 + 徽章 + 升級」的三個體感核心。
