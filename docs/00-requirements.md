## 1. 一句話定義

把大會變成一場「以量子知識地圖為棋盤」的個人探索遊戲：參加者用網站登入成為冒險者，參與議程、完成任務累積 QXP，在地圖上點亮節點並升級，最後帶走一枚能回顧自己探索成果的 NFC 冒險徽章。

**設計主張**（來源明寫，不可在實作時反轉）：
1. 積分只是啟動動機，終極獎勵是帶走的知識與想法。
2. 不設排行榜、個人資料不公開 → 避免比較，把注意力留在議程。
3. 任務種類要多樣（不只聽講），升級條件故意綁「不同種類」任務。

## 2. 角色與名詞

| 名詞 | 定義 |
| --- | --- |
| 冒險者 | 完成報到並登入網站的參加者 |
| QXP | Quantum Exploration Points，量子探索值，唯一的積分通貨 |
| 冒險等級 | Q → S → SS → SSS，由「QXP 門檻 AND 升級條件」共同判定 |
| 探索區域 | 地圖的三個大分區（認識／解構／連結量子） |
| 內容標籤 | 掛在議程上的 1～3 個核心概念，依知識類別上色 |
| 已探索 | 該議程指定的探索任務已完成，節點由白底黑字變黑底白字 |
| 場外任務 | 講座之外的實體互動（圈圈叉叉、量子邏輯閘收集） |
| 工人 | 現場執行計分、審核、兌換的工作人員 |

〔推論〕系統角色需另分三層權限：`attendee`（冒險者本人）、`worker`（掃碼計分、初審）、`admin`（設定規則、複審、匯出）。

## 4. 冒險等級

### 4.1 等級表（來源原文）

| 等級 | QXP | 升級條件 |
| --- | --- | --- |
| **Q｜初始化 Qubit** | 0 | 登入量子冒險者網站 |
| **S｜疊加思行者** | 50 | 完成 1 次答題 |
| **SS｜干涉解碼者** | 150 | 上傳 1 份心得筆記 |
| **SSS｜糾纏先鋒** | 400 | 上傳 1 次重點彙整（AI 審核通過）**或** 完成任意場外任務 |

- 兩項條件皆完成才解鎖；等級只升不降。
- 最終等級於大會尾聲結算，之後不再變動（爭議補登除外）。

### 4.2 判定邏輯（實作規格）

```
level(user) = 最高的 L ∈ {Q,S,SS,SSS}
              使得 qxp(user) >= L.minQxp  AND  all(L.requirements)
```

`requirements` 必須是「可從帳本／提交物推導」的計數，不能靠人工口頭認定：

| 條件 | 判定依據 |
| --- | --- |
| 完成 1 次答題 | `quiz_attempts` 該場已提交（不要求全對） |
| 上傳 1 份心得筆記 | `submissions(kind='note')` 狀態 ∈ {submitted, approved}，字數達門檻 |
| 重點彙整通過 | `submissions(kind='summary')` 狀態 = approved（AI 通過 + 人工通過） |
| 完成任意場外任務 | `task_scans` 至少一筆該任務「完成」階段 |

〔推論〕門檻與條件**不可寫進程式碼**，要放在 `scoring_rules` / `level_requirements` 資料表，活動前可改不用重新部署。

### 4.3 數值校準警示 ⚠

依 2026-11-10 議程草案：30 筆議程中可計分者約 16 場（11 talk + 2 workshop + 2 keynote + 1 roundtable；多軌重疊，單人一天實際可參與約 8–11 場）。

| 人格 | 行為 | 估算 QXP | 等級 |
| --- | --- | --- | --- |
| 路過型 | 3 場答題 + 1 篇心得 | 30 + 30 = 60 | S（條件✓） |
| 認真型 | 6 場答題 + 4 篇心得 + 交流滿 + 2 場外 | 60 + 120 + 30 + 60 = **270** | SS |
| 全力型 | 8 場答題 + 8 篇心得（無講者回覆）+ 交流滿 + 2 場外 | 80 + 240 + 30 + 60 = **410** | SSS（場外任務✓） |
| 全力型＋彙整 | 上一列 + 1 篇重點彙整 | 460 | SSS |

**問題**：SSS 的 400 分幾乎等於「每一場都要寫心得」。而 SSS 的升級條件偏窄（彙整要人工審、場外任務只有 2 種），現場審核會變成瓶頸 → 見 `Q-6`、`Q-14`。建議二選一：
- (A) 維持 400，但把心得「講者回覆 +15」與彙整 50 分視為主要達成路徑，並保證現場審核 15 分鐘內完成。
- (B) 下修 SSS 至 350，或把心得基礎分提到 35。

| 認識量子｜基礎知識 | 解構量子｜原理與運作 | 連結量子｜應用與未來 |
| --- | --- | --- |
| 量子與古典資訊<br>Bit、Qubit 與量子態<br>疊加、干涉、糾纏與測量<br>量子電腦的基本組成<br>量子計算模型概覽<br>量子計算能與不能做什麼 | 量子位元硬體與控制<br>量子閘、電路與測量<br>量子演算法<br>軟體、編譯與模擬<br>雜訊、退相干與錯誤緩解<br>量子錯誤修正與容錯<br>基準測試、驗證與資源估算 | 科學與產業應用<br>量子優勢與可行性<br>量子古典混合運算<br>容錯量子計算路線<br>企業導入與產業生態<br>人才、政策、標準與倫理 |

⚠ **品牌衝突**：主站（`qracon_web_2026`）已定案「純黑白灰、零色相」。這裡要求 6 類別上色 → `Q-2`。

### 5.3 節點狀態與視覺

| 狀態 | 表示 |
| --- | --- |
| 未探索 | 白底、黑框、黑字 |
| 已探索 | 黑底（或深灰）、黑框、白字 |
| 已探索 + 有心得 | 額外顯示 📄 記號 |

連線語意：實線＝議程的核心概念，虛線＝兩個相關概念之間的關聯。

### 5.4 介面與版面

- 手機優先（現場幾乎都是手機）；另印 A4 紙本地圖發放。
- 來源自陳的風險：**議程一多，節點連線會亂**（原文：「感覺多個議程很容易讓版面亂掉」）。

〔推論〕可行做法：地圖只在「標籤層」密集連線，議程節點用所屬標籤分群、不畫跨群連線；預設縮放只顯示三大區域 + 標籤，點進去才展開該標籤下的議程。這需要一張「標籤→議程」的資料表，不是手畫 SVG。→ `Q-3`

### 5.5 學習難度

| 標示 | 定義 | 網站要求 |
| --- | --- | --- |
| ★ | 無需先備，不具量子背景也能懂大部分 | 不顯示先備知識 |
| ★★ | 需要基本量子概念，不必研究或實作經驗 | 議程頁註明先備知識（如矩陣、傅立葉） |
| ★★★ | 需要特定領域知識才能完整理解 | 同上，且需更具體 |

### 5.6 議程重點彙整（待討論完善）

- 問題：同一時段多場議程重疊，參加者必須取捨。
- 解法：讓完整參與者投稿該場「重點彙整」（知識與資訊呈現，**不是個人心得**），工人篩選後放上網站。
- 介面最多呈現 3 篇，以輪播方式呈現。
- 投稿被採用者可獲額外 QXP（見 §6）。
- 風險：這是唯一需要「內容審查」的任務 → 人力與 SLA 是專案成敗關鍵（`Q-6`）。

## 6. 計分（量子探索值）

### 6.1 任務與分數

**實體任務**

| 任務 | 計分 | 觸發 |
| --- | --- | --- |
| 講座提問 | 10 | 第一次提出與該場相關的問題 |
| 講座提問（被講者回答） | +20 | 講者回應該問題 |
| 圈圈叉叉（對戰） | 15 | 第一次參與 |
| 圈圈叉叉（戰勝） | +15 | 該局獲勝 |
| 量子邏輯閘收集 | 5 | 第一次收集到元件 |
| 量子邏輯閘收集（完成運算） | +25 | 完成指定運算 |

**網站任務**

| 任務 | 計分 | 上限／細則 |
| --- | --- | --- |
| 講座內容答題 | 0–10 | 5 題選擇或是非；按答對率給分；共 2 次機會 |
| 心得筆記 | 30 | 每人每場 1 次；講者回覆問題 +15 |
| 議程重點彙整 | 20 + 30 | AI 審 ≥60 得 20；人工審通過再 +30 |
| 交流版 | 5／次 | 上限 30；每人每討論串最多計 1 次 |

### 6.2 計分規則（來源）

1. 講座提問：每人每場最多計分 1 次，問題需與講座內容相關。
2. 場外互動：依各活動規則給分。
3. 答題：2 次機會，按答對率給分；首次答錯者，看過解析後重答正確可得**該題一半**分數。於講座 QA 時間開放，30 分鐘後關閉。5 題、約 3–5 分鐘可完成。
4. 心得筆記：每人每場 1 次，需具備回顧價值才計分。（是否給開頭引導？最低字數？上傳後可否編輯？→ `Q-4`）
5. 交流版：自由發表，但只有具實質內容且與議程相關者計分；發文或回應都可得分；每人每討論串最多 1 次。
6. 同類型任務要設總計分次數上限。

### 6.3 工程化的計分原則〔推論，必須落實在程式〕

1. **帳本制**：每一分都是一筆 `score_event`，永不直接改總分；總分是 `SUM(points)`。
2. **冪等**：每筆計分有 `dedupe_key`（例：`quiz:<slot>:<user>`、`note:<slot>:<user>`、`scan:<task>:<stage>:<user>`），重複呼叫回傳同一結果。
3. **上限是資料**：`total_cap`、`per_slot_cap`、`per_day_cap` 由規則表驅動，改數字不動程式。
4. **可撤銷**：錯發用反向事件（`reversed_by`）抵銷，不刪除，保留審計軌跡。
5. **所有加分都有 actor**：系統、工人或 admin 的 id 都要記。
6. **答題按題計分**：5 題 × 2 分，重答每題得 1 分，不能整份重算。
7. **時窗伺服器端判定**：前端倒數不可信。

### 6.4 防刷分對照表

| 風險行為 | 機制 |
| --- | --- |
| 同場重複提問 | `per_slot_cap=1` + 人工確認 |
| 一句話灌交流版 | 最低字數 + 每串 1 次 + 總上限 30 + 人工抽查 |
| 重送答題拿兩次機會 | `UNIQUE(user, slot, attempt_no)`，`attempt_no ≤ 2` |
| 心得複製貼上／AI 代寫 | AI 審輔助標記 + 抽查；不為此增設懲罰（`Q-4`） |
| 工人誤按重複掃碼 | `dedupe_key` |
| 共用報到代碼 | 首次登入綁裝置 cookie；異常由 admin 重置 |

## 7. 交流版

定位：所有任務中權重最低的加分項，用來降低「無意義留言水積分」的動機。

**發文格式**

| 欄位 | 選項 |
| --- | --- |
| 所屬議程 | 所有議程，自選一項 |
| 交流類型 | 提問／補充資訊／延伸討論，自選一項 |
| 交流內容 | 依類型給對應提示 |

**提示文案**
- 提問：你想知道什麼？
- 補充資訊：你想補充什麼資訊？可附上來源或相關連結。
- 延伸討論：這個議題還可以從什麼角度繼續討論？

〔推論〕以「議程 = 討論串」建模（每人每串限 1 次計分），貼文與回覆共用同一資料表，`parent_id` 最多一層。

## 8. 獎勵

### 8.1 抽獎券

- QXP 達指定里程碑可獲得抽獎券，抽大會周邊。
- 每人最多 X 張（`Q-8`），取得不扣 QXP。
- 〔推論〕建議里程碑 100／250／400 → 最多 3 張，現場憑券號兌換。

### 8.2 冒險徽章

- **實體**金屬 NFC 吊飾 + 壓克力配件。
- 感應後登入網站 → 看「個人探索成果」與「未來冒險建議」。
- 個人探索成果：最終等級、累計 QXP、行動總結、心得筆記、地圖探索足跡。
- 行動總結範例：「參與 7 場議程，觸及 12 個知識概念，跨越 3 大探索區域」。
- 未來冒險建議：依興趣主題與知識背景推薦後續議題與學習資源。
